# Corrections and result challenges

Open an issue with the query ID, run and evidence version, company, disputed condition,
and dated public source. For pricing, cite the tariff and identify the cost view. For
identity, state whether the entity is a parent, subsidiary, brand, operator, or facility
owner. A challenge may support Avina or any competing provider.

Investigate the original saved result and evidence before changing a judgment. Distinguish
search errors, missing evidence, identity mistakes, incorrect criteria, judge mistakes,
and calculation bugs. Preserve the original artifacts and the stated comparison scope.

Accepted corrections have a dated explanation and a new dataset, evidence, judgment, or
publication version as appropriate. Regrade all affected provider results against the same
new evidence. Corrections must not silently replace unfavorable results, add a winning
configuration after the fact, or reuse a retired query ID. Earlier public bundles remain
available with a link to their correction.

Use [blind human review and identity maps](judges.md) for reviewed corrections, and
[CONTRIBUTING.md](../CONTRIBUTING.md) for code and data changes. Share redacted publication
bundles instead of private raw run directories.
